## 新增：界面风格可切换

「主题设置 → 界面风格（UI 体系）」现在可以在三套之间切换：

| 风格 | 覆盖范围 | 特征 |
| --- | --- | --- |
| **Miuix**（默认） | 全部 | 小米 HyperOS 观感，工程原有界面 |
| **Material 3 Expressive** | 全部 17 页 | MD3E 的弹性动效与分段圆角卡片 |
| **麻薯 Mochi** | 关于 / 更新 / 隐私 | iOS 分组卡片、连续圆角、Ionicons |

切换立即生效并落盘，不需要重启。

### 为什么是「页面组」而不是「换肤」

换肤只能改颜色和圆角，改不了卡片结构、列表行高、浮层形态。所以这里做成
**独立的页面组**：每一套是一组自己的页面实现，共用同一份业务状态与动作。

支撑它的是一个接口：

```kotlin
interface ZhiPageSet {
    val id: String
    @Composable fun About(...) = MiuixPages.About(...)   // 默认回落到 Miuix
    // … 十七个页面
}
```

每个方法都带 `@Composable` **默认实现**，指向 Miuix。于是：

- 默认组是空实现 —— 全部回落，等于"什么都没改"；
- 新风格**只覆写想改的页面**，其余自动沿用默认。

这条「回落」是关键。若用抽象方法，新风格必须先写满十七页（约一万行）才能编译通过
—— 那等于不允许渐进验证，第一个像素都看不到。麻薯组就是只写了三页就装上去看的。

Material 3 Expressive 覆盖全部十七页，是这套结构目前为止最完整的一次验证。

### 切换失败会怎样

选择以页面组 id 保存为字符串。若某个组在后续版本被移除或改名，读取时**回落到默认组**
—— 与配色预设、字体族等设置同一套兜底。不会白屏，也不会卡在一个不存在的风格上。

## 流畅度

### 上滑加载历史不再跳到顶部

往前补一页历史时，第一个助手回合的**标题键会变**：那个键取的是「这一轮首成员」的 id，
而新补进来的消息会并入它并成为新的首成员。对列表而言那是一条**全新条目**，
之前记住的滚动锚点全部作废，位置被夹到某项上 —— 表现就是"加载完跳到最上面"。

现在给每个回合一个按位置对齐的**稳定键**，只在前插且未切会话时启用。
切会话、回到最新这类"整份替换"必须让它彻底重建，所以不能一概而论。

### 打开设置页不再把对话流顶到底

跟随意图曾被跨页面保留：从设置页回来时，一次性把"要继续跟随"判成真，
把用户正在读的历史顶走。

现在恢复后的第一轮不当作"用户要继续跟随"—— 真正的内容变化（流式输出、新消息）
仍然正常跟随。

### 重组开销

开启 Compose **强跳过**（`enableStrongSkippingMode`）。此前工作区那个含两百多个字段的
状态类被判为不稳定，任何一次流式输出都会让整棵对话流重组；判据从"类型必须稳定"
放宽到"`equals` 相等即可"之后，状态没变就整页跳过。

> 代价：强跳过依赖 `equals`。本工程状态类都是 `data class`，语义正确；
> 今后新增状态类也必须继续用 `data class`，否则会出现"内容变了却不重组"。

### 测量能在正式包里开了

帧耗时与重组计数探针此前绑在 `BuildConfig.DEBUG` 上 —— 而真机问题几乎只在正式包
出现（调试包的手感、GC 行为、包体都不同）。结果是**一直拿不到数据**。

现在由构建参数控制：

```bash
./gradlew :app:assembleRelease -PframeTrace=true
```

平时不传这个参数，探针被完整编译掉，零开销。

## 修复

### 顶栏与底栏的模糊

上一轮为省一次整屏录制，在页面切换期间**暂停了背景捕获**。实际表现：

| 时刻 | 行为 | 画面 |
| --- | --- | --- |
| 切换后 420ms 内 | 不再把内容录进离屏层 | 模糊块取不到背景 → **半透明** |
| 420ms 后 | 恢复录制 | **变回模糊** |

若那次暂停没有正常结束（组合提前离开、effect 被取消），模糊会**一直不出现**。

该机制已整体移除，恢复为始终捕获。它当初是为缓解单帧 166ms 尖峰加的推测性优化，
没有实测证明有效，却造成了确定的视觉回归 —— 先保住功能。

### 移除麻薯导航栈

它会在转场期间**同时组合上下两页**，而工作区那一屏极重。更麻烦的是压栈的下层页
**始终保有组合**，于是对话流的跟随逻辑在设置页打开时仍在跑 —— 这正是
"开设置页对话流置底"的结构性来源。

已回到 Miuix 自己的页面栈（`NavDisplay` + `NavKey`）。

## 已知问题

- **「预测性返回手势」开关是空的**：它挂的 `WindowNavigationEventBridge` 在主窗口里
  因为 `windowDispatcher === inheritedDispatcher` 直接返回。修它需要动 `targetSdk`
  （系统预测性返回动画要求 `targetSdk ≥ 33`），影响面超出一次修补的范围。
- **更新页「下载 APK → 交给系统安装器」这条链路仍未真机验证**。本仓库在 1.0.0
  之后才有了第一个 Release，条件刚刚具备但还没走过一遍。
- **主题页的三台「手机示意图」是手画的占位方块**，还没改成用真实组件缩小渲染。
- **对话流快速滑动的卡顿仍在**：已确认是 GC（单次会话累计 3 秒），
  但尚未把分配定位到具体对象。强跳过减少了重组，没有根治。
