# 1.0.0

首个正式版。版本号从 `0.2` 升到 `1.0.0` —— 它表示**界面与设置的结构已经定下来**，
不表示此后不再改（下面这些条目本身就是这一轮刚改的）。

> ⚠️ 本项目仍处于快速迭代阶段，大部分改动由 AI Agent 协作完成，
> 尚未经过充分的人工审查与长期稳定性验证。请自行评估风险。

---

## 新增：系统更新页

「关于」页中间那个大 **ZhiCode** 字现在可以点，进去是检查更新页：

- 上半是品牌字与版本号，一条发丝线（`Dp.Hairline`，恒定一个物理像素）下面**直接是更新内容**；
- **更新内容的来源随状态切换**：有新版本时显示那个版本的发行说明（来自仓库的 Release，
  经极简 Markdown 分流成「小节标题 + 正文」）；没有新版本时显示**当前版本**的说明。
  两边用同一套结构渲染，所以看不出哪一段是远端来的；
- 有新版本时底部出现「下载并安装」，下载完交给系统安装器；
- 「关于」页的版本卡片里还有一行「有新版本 x.y.z」—— **只在真的检测到新版本时出现**，
  其余状态不显示。

状态提示（「已经是最新版本」「发现新版本」）走**系统吐司**，不占页面空间。

网络层没有任何新依赖，用的还是裸 `HttpURLConnection`，并且：不跟随重定向、
响应体边读边计数限上、失败原因分开报（网络不可达 / 403 限流 / 非 2xx / 解析失败 /
列表为空 —— 这五件事用户能做的动作完全不同）。

## 界面修复

### 字号回到 Miuix 规范

此前把整套字阶整体压了一档（`title1` 32→24、`main` 17→14）。代价是实的：

- 偏离库的设计规范 —— 整套 UI 建在 Miuix 之上而字体不是它规定的尺寸；
- 层级被压平 —— 四档标题挤进 9sp 区间，`body1` 与 `body2` 只差 1sp，几乎分不出来；
- 下游组件按规范布局（行高、图标底板、`SmallTopAppBar` 高度），字号一改就要靠页面各自打补丁。

现在按库的规范值来。**要调观感请调排版，不要再压字阶。**

### 深浅色模式下图标不再发灰

深色的弱化文字/图标色此前一直没被覆盖，沿用了库自带的蓝灰 `#787E96`——
在面板上对比度只有 **3.86:1**。摘要文字是 `#80FFFFFF`（50% 白），在卡片上 4.66:1。

改后：

| | 新值 | 面板 `#242424` | 卡片 `#2D2D2D` |
|---|---|---|---|
| 弱化文字/图标 | `#9A9AA2` | 5.56:1 | 4.93:1 |
| 摘要文字 | `#9E9EA6` | 5.84:1 | 5.18:1 |

摘要色用**不透明**实色而非半透明白 —— 半透明会跟底下卡片混色，
同一段文字在页面底色和在卡片上灰得不一样，那正是「有些地方灰得不一样」的来源。
Monet 与固定色板两条路径都接上了（Monet 那条之前完全没修正）。

### 侧栏

- `systemBars` inset 移到面板本身，不再顶进状态栏把汉堡按钮那一行压住；
- 面板加一个空 `clickable` 消耗点击 —— 原先点空白处会穿透到遮罩上把侧栏关掉
  （Miuix 不带 `onClick` 的 `Surface` 不注册 pointerInput）。

### 工具组与单条工具同一个壳

折叠起来的工具组此前是裸 `Column`（没有卡片底），而单条工具包了 `Card`。
同一批里两种长相。现在组也套同一层壳、同样的圆角与内边距。

### 附件按类型分列

文件与图片不再共用一条横向窄条 —— 文件卡片会被右边缘裁掉一半，而且两者长得几乎一样，
选三四张之后认不出哪张是哪张。现在：

- 图片仍是缩略图行（靠**画面**辨认）；
- 文件是整宽卡片（靠**名字 + 体积**辨认，图标底板 + 标题 + 体积第二行）。

底部提示条从「已附加：xxx（125KB）」改成「已附加 N 个文件」——
体积已经显示在卡片自己身上，提示条再念一遍是同一件事说两处。

## 行为修复

### 上滑加载更早的消息不再置顶

往前补一页历史时，第一个助手回合的**标题键会变**：`TurnLayout.Block.Turn.key`
取的是「这一轮首成员」的 id，而新补进来的消息会并入它并成为新的首成员。
对 `LazyColumn` 来说那就是一条**全新的 item**，之前记住的滚动锚点全部作废，
位置被夹到某项上。

现在给 `Turn` 加了独立的 `stableKey`，按位置对齐新旧两块、成员有交集才钉住旧键，
让那一块对列表而言仍是同一块。**只在前插且未切会话时启用** ——
切会话、回到最新这类「整份替换」必须让它彻底重建。

### 深浅色选择不再被改回去

深浅模式实际有**三份**：`themeSettings.mode`（真源）、`state.themeMode`（缓存）、
`SettingsDraft.themeMode`。而 `SettingsDraft.applyTo()` 会把 draft 里的值写回 state：

```kotlin
themeMode = themeMode,
themeSettings = state.themeSettings.copy(mode = themeMode),
```

改主题的两个入口原先**只改前两份、不动 draft**。于是只要之后发生任意一次
`applySettingsDraft()`（设置页里点个开关就会走），旧值就把新值覆盖回去。
因为是真的写回 state，所以**再进设置页也显示旧值**。

现在三处一起更新。

### 主题改动一定落盘

`flushSettings()` 的第一句是 `if (settingsPersistJob == null) return`，
而 `updateThemeSettings()` 从不设置那个 job —— 于是从主题页**侧滑返回**时
（不走 `closeThemePage` 那条显式持久化路径），改动只活在内存里，进程被划掉就丢。

现在登记待落盘标记，关设置页与切后台都会兑现，且同时写 `ThemeStore` 与
`SettingsDraft` 两份存储。

## 其它

- **仓库地址修正**：`PROJECT_URL` 从 `iqisge-gif/IQ-Code-Android` 改成
  `zhizhu0002/ZhiCode`，并挪到 `model/ProjectRepo.kt` 作为唯一真实来源
  （`REPO_SLUG` / `PROJECT_URL` / `RELEASES_API_URL` / `RELEASES_PAGE_URL`
  全部由它派生）。`THIRD_PARTY_LICENSES` 里 IQ Code 那条的 `iqisge-gif`
  是对**上游的署名，保持不变**。
- **分隔线收敛**：`ZhiHorizontalDivider` / `ZhiVerticalDivider` 补 `thickness` 参数；
  `Markdown.kt` 三处手搓的 `Box + height(1.dp).background(...)` 改成 Divider ——
  手搓那条在 3x 屏上是 3px，比系统自带的线粗一截。
- **隐私政策**补一条：进关于页与更新页会请求 `api.github.com` 的 Releases 接口，
  只读公开信息、不带任何用户数据与应用标识。
- **单元测试工作目录**固定为工程根。不设它时 Gradle 用模块目录，于是
  `File("app/src/main/java")` 解析成 `app/app/...`、`File("NOTICE")` 变成 `app/NOTICE`，
  4 条测试失败并报出「找不到源码目录」这种像工程坏了的信息。
- **`ChangeLogTest` 改为从 `app/build.gradle` 读 `versionName`**，不再手工同步 ——
  上一版写死成 `"0.2"`，这次升级差点漏掉，而漏掉的后果是更新页永远显示
  「这个版本没有留下更新说明」，且没人会想到去查一个测试。

## 已知问题

- **「预测性返回手势」开关目前是空的**：它挂的 `WindowNavigationEventBridge`
  在主窗口里因为 `windowDispatcher === inheritedDispatcher` 直接返回，
  所以开关切换没有任何效果。修它需要动 `targetSdk`（系统预测性返回动画要求
  `targetSdk ≥ 33`）或自己包一层 dispatcher，影响面超出一次修补的范围。
- **更新页的「下载 APK → 交给系统安装器」这条链路尚未真机验证**：
  本仓库此前没有任何 Release，那条路径走不到。发这个 Release 之后才有条件验证。
- 主题页那三台「手机示意图」是手画的占位方块，还没改成用真实组件缩小渲染。
